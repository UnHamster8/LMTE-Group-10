
# Pebble — Group 10 Interpreter

Pebble is a small **interpreted programming language** implemented in Python 3. The project includes a lexer, recursive-descent parser, Abstract Syntax Tree (AST), semantic validation, evaluator, command-line interface and automated tests.

The interpreter supports integer and Boolean operations, variables, conditional statements, loops and functions. No third-party dependencies are required.

## 2. Quick Start

Python **3.10+** is required.

Run the following commands from the project root:

```sh
python main.py examples/basic.peb
python main.py examples/control_flow.peb
python main.py examples/functions.peb
```

To display the tokens generated by the lexer:

```sh
python main.py --tokens examples/basic.peb
```

To run the complete automated test suite:

```sh
python -m unittest discover -s tests -v
```

On systems where `python` does not refer to Python 3, use `python3` on macOS/Linux or `py -3` on Windows.

Source files use UTF-8 encoding. The program exits with status `0` on success or `1` on a Pebble or file error. Error messages are written to stderr.

## 3. Language Syntax

Pebble uses the following keywords:

`let`, `say`, `if`, `else`, `while`, `do`, `end`, `func`, `return`, `true`, `false`

All keywords are lowercase and case-sensitive.

Variable names follow the pattern `[A-Za-z][A-Za-z0-9_]*`. Integers use decimal digits, and `//` introduces a single-line comment.

Simple statements end with `;`, while compound statements end with `end`. Indentation is used for readability and does not affect execution.

### Grammar

The main language grammar is defined as follows:

```text
program    = { function | statement } ;
block      = { statement } ;
function   = "func" name "(" [ parameters ] ")" "do" block "end" ;
statement  = "let" name "=" expr ";" | "say" expr ";" | "return" expr ";"
           | "if" expr "do" block [ "else" block ] "end"
           | "while" expr "do" block "end" ;
parameters = name { "," name } ;
arguments  = expr { "," expr } ;
expr       = equality ;
equality   = comparison { ("==" | "!=") comparison } ;
comparison = sum [ ("<" | "<=" | ">" | ">=") sum ] ;
sum        = product { ("+" | "-") product } ;
product    = unary { ("*" | "/") unary } ;
unary      = "-" unary | primary ;
primary    = integer | "true" | "false" | "(" expr ")"
           | name [ "(" [ arguments ] ")" ] ;
name       = letter { letter | digit | "_" } ;
integer    = digit { digit } ;
```

### Operator Precedence

Operator precedence, from highest to lowest:

1. Parentheses and function calls
2. Unary minus
3. Multiplication and division (`*`, `/`)
4. Addition and subtraction (`+`, `-`)
5. Ordering comparisons (`<`, `<=`, `>`, `>=`)
6. Equality comparisons (`==`, `!=`)

Binary operators are left-associative. Chained ordering comparisons are not supported.

## 4. Language Semantics

### Variables and Output

- `let` creates or updates a variable.
- Variables must be assigned before being read.
- `say` prints one result per line.
- Boolean values are displayed as lowercase `true` or `false`.

### Expressions

- Arithmetic and ordering operations require integer operands.
- Equality comparisons require matching operand types.
- Conditions must evaluate to Boolean values.
- Integer division truncates toward zero.

### Control Flow

- `if/else` selects a branch based on a Boolean condition.
- `while` repeatedly executes a block while its condition is true.
- The condition is reevaluated before each loop iteration.

### Functions and Scope

- Functions must be defined before execution reaches their calls.
- Each function call creates a new local scope.
- Local variables are read before global variables.
- Local assignments do not modify global variables.
- Functions must return a value.
- Nested function definitions are not supported.

### Error Handling

Pebble provides error messages with source positions for:

- Invalid characters and syntax errors
- Duplicate function parameters
- `return` statements outside functions
- Undefined variables and functions
- Invalid operand types
- Division by zero
- Incorrect function argument counts
- Missing function return values

Static validation checks top-level `return` statements and duplicate parameters before evaluation. Other errors are detected during execution.

### Language Limitations

The current implementation does not support strings, floating-point numbers, lists, objects, closures or native-code generation.

## 5. Internal Implementation

Pebble follows an interpreter architecture:

```text
Source File
    |
    v
Lexer
    |
    v
Tokens
    |
    v
Parser
    |
    v
Abstract Syntax Tree (AST)
    |
    v
Semantic Validation
    |
    v
Evaluator
    |
    v
Program Output
```

### Project Structure

| Path | Responsibility |
| --- | --- |
| `pebble/tokens.py` | Token definitions and source positions |
| `pebble/lexer.py` | Lexical analysis and token generation |
| `pebble/parser.py` | Recursive-descent parsing and operator precedence |
| `pebble/ast_nodes.py` | Abstract Syntax Tree structures |
| `pebble/evaluator.py` | Semantic validation, environments, execution and function calls |
| `pebble/errors.py` | Error categories and line/column formatting |
| `main.py` | Command-line execution, file handling and token debugging |
| `examples/` | Example Pebble programs |
| `tests/` | Unit, integration and regression tests |
| `TEST_REPORT.md` | Testing results and validation documentation |

Pebble is an **interpreter**, not an ahead-of-time compiler.

It directly evaluates the AST without generating three-address code (TAC) or machine code. The AST serves as the intermediate representation, and code optimisation is not implemented.
